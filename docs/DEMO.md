## 2. להפעיל את המערכת — לחיצה כפולה

בתיקייה `scripts\` יש שלושה קיצורים:

| קובץ | מה עושה |
|---|---|
| **`scripts\run_tracking.bat`** | ← **זה מה שמריצים בהצגה** |
| `scripts\recalibrate.bat` | רק אם החומרה זזה |
| `scripts\radar_replay.bat` | קונסולת המכ"ם מהקלטה, בלי חומרה — לחזרות |

**לחיצה כפולה על הראשון.** נפתח חלון שחור (הפלט), ואחריו חלון המצלמה וקונסולת המכ"ם, שעולה עם מסך פתיחה של כ-3 שניות. לעצירה: לסגור את חלון המצלמה או ללחוץ `Q`.

בקונסולה: **`F`** מסך מלא, **`M`** השתקה. למקרן: לגרור קודם את חלון המכ"ם למסך המקרן, ואז `F`.

> אם משהו משתבש, החלון השחור **נשאר פתוח** ומראה את השגיאה. הסיבה הנפוצה: חלון Python קודם עדיין פתוח ומחזיק את המצלמה.

## 3. מה להראות בחלונות בזמן ההדגמה

נפתחים **שני חלונות**, והם משלימים זה את זה:

### חלון המכ"ם — הכי מרשים ויזואלית

זו התצוגה שהובטחה בהצעת הפרויקט: מיקום המטרה על **צירים קוטביים** — זווית ומרחק — עם סימון נעילה אדום, ומעליה קונסולה שלמה.

| מה מצביעים עליו | מה אומרים |
|---|---|
| הנקודה הזוהרת + השובל | "המטרה, והמסלול שלה בשתי השניות האחרונות" |
| מבט מלמעלה + מבט צד | "אותו כדור משני כיוונים, בקנה מידה — ביחד זה מיקום בתלת-ממד" |
| `RANGE 56.7 cm` | "המרחק — **מחושב מההיסט בין שתי העיניים**" |
| `AZIMUTH -16.7 deg` | "הזווית ביחס לציר המצלמה" |
| הקו האדום | "לאן הצריח מכוון ברגע זה — רואים אותו רודף אחרי הכדור" |
| החץ הלבן | "לאן הכדור יגיע בעוד חצי שנייה" |
| `TARGET LOCKED` + צליל | "נעילה — הלייזר יורה" |
| גרף המרחק | "מטוטלת שמתקרבת ומתרחקת מציירת גל" |
| מקרבים את הכדור → הנקודה **יורדת** פנימה | "רואים אותה נכנסת לטבעות הקרובות" |

הדגמה חזקה: **להזיז את הכדור לרוחב ולראות את הנקודה חוצה את המגזר** — זו התנועה במרחב האמיתי, לא בפיקסלים.

**אם ישאלו "זה מכ"ם אמיתי?"** לא: אין כאן שידור רדיו. המיקום אמיתי ומגיע משתי המצלמות, והתצוגה בנויה כמו מכ"ם. קו הסריקה, הכתמים הקטנים והצלילים הם קישוט. הסנטימטרים הם הערכה (בסטייה גסה של כ-15%), כי המרחק לא כויל בסרט מדידה.

### חלון המצלמה — ההסבר לאיך זה עובד

מציג את **שתי העיניים** זו לצד זו, וזה עצמו הסבר ויזואלי לעומק:

| מה מצביעים עליו | מה אומרים |
|---|---|
| עיגול ירוק (שמאל) + כתום (ימין) | "שתי המצלמות מזהות את אותו כדור" |
| `LOCK disp=32` | "ההפרש בפיקסלים בין העיניים — **ככה אנחנו יודעים את המרחק**" |
| הכדור מתקרב → `disp` **עולה** | "ההיסט גדל ככל שהעצם קרוב יותר — בדיוק כמו שתי העיניים שלנו" |
| `COAST (holding)` | "המטוטלת עוצרת רגע בקצה; המערכת מחזיקה כיוון במקום לכבות" |
| מרחיקים את הכדור → הלייזר נכבה | "הלייזר דולק **רק** כשיש נעילה אמיתית" |

**ההדגמה הכי משכנעת:** להזיז את הכדור לאט לרוחב ולראות את הצריח עוקב, ואז **לעצור אותו** ולראות שהלייזר נשאר עליו.

## 4. איך מציגים את הקוד

**פתחו את כל הפרויקט ב-VS Code בבת אחת:**

```bash
code aeroeye-3d
```

או: לחיצה ימנית על התיקייה → `Open with Code`.

### סדר ההצגה — חמישה קבצים, סיפור אחד

**① `src/main.cpp` — הקוד שרץ בתוך הארדואינו**

> "יש כאן **שני מעבדים**, וזו החלטת תכן. המחשב עושה ראייה ממוחשבת, והארדואינו מייצר את אותות ה-PWM — כי תזמון מדויק זה מה שמערכת הפעלה **לא** מבטיחה."

להצביע על `stepToward` ועל האישור המיידי:
> "הלוח מאשר כל פקודה **מיד** ואז רודף אחרי היעד ברקע ב-1° כל 2 מילישניות. אם הוא היה מסיים את התנועה לפני האישור, המחשב היה נחסם ומאבד פריימים."

**② `vision/stereo.py` — איך נמדד המרחק**

קובץ קצר, ולכן קל להראות:
> "פריים אחד של 640×240 הוא בעצם **שתי מצלמות** של 320×240. ההפרש האופקי במיקום העצם בין העיניים נותן את המרחק."

**③ `vision/detector_dark.py` — לב המערכת**

**ה-docstring בראש הקובץ הוא הסיפור המלא** — שלוש הגישות והמספרים שלהן. שווה להקרין אותו כמו שהוא:

> "ניסינו שלוש שיטות ומדדנו כל אחת מול אותם 15 פריימים:
> - **חיסור רקע (MOG2)** — מזהה *שינוי*, אז מטוטלת שעוצרת בקצה נעלמת ממנו לגמרי. עגלגלות 0.15–0.35.
> - **הפרש מול תמונת ייחוס** — הייחוס **מתיישן**, כי למצלמה יש בקרת רווח אוטומטית שלא ניתן לכבות.
> - **ניגודיות מקומית** ✅ — משווים כל פיקסל לסביבתו במקום לתמונה שמורה. עגלגלות **0.73–0.87**."

ואז הפרט שהכי מרשים:
> "המוט הכהה נדבק לכדור ויצר צורה מוארכת שנפסלה. **פתיחה מורפולוגית בדיסק של 29 פיקסלים** — רחב מהמוט, צר מהכדור — מוחקת את הזנב. הפרמטר הבודד הזה שינה מ-5 ל-8 נעילות מתוך 10."

**④ `vision/track_motion_3d.py` — האינטגרציה**

להצביע על הפונקציה `aim()`:
> "מפיקסל + מרחק לזוויות, לפי מודל ריבועי, ועליו תיקון שמדדנו מול הכדור עצמו."

**⑤ `vision/calib_ball.py` — הכיול**

> "במקום לכוון ולמדוד כמה החטאנו, הצריח **ממרכז את עצמו** על הכדור בלולאה סגורה, ורק כשהוא מתכנס הנקודה נרשמת. כל נקודה אומרת 'הזוויות האלה מציבות את הלייזר בדיוק כאן'."

## 6. שתי שאלות שסביר שיישאלו

**"למה לא זיהוי לפי צבע? כדור צהוב זה קל."**
> "מדדנו — המצלמה **מונוכרומטית** בפועל. ההפרש המקסימלי בין ערוצי הצבע בכל התמונה הוא 2 רמות מתוך 255. אין שם צבע לעבוד איתו."

**"איך בחרתם את מודל הכיול?"**
> "ב-**cross-validation**, לא לפי התאמה לנתונים. מודל ריבועי בן 7 פרמטרים קיבל 97% כשבדקנו אותו על הנתונים שעליהם אומן — אבל רק 85% בבדיקה חוצה. הוא שינן במקום להכליל, אז בחרנו במודל הליניארי."

## 7. מה שכדאי להציג ביושר כמגבלה

- **עקיבה מהירה מפגרת.** ההשהיה מקצה לקצה לא נמדדה, ופרמטר החיזוי נבחר שמרנית. זו העבודה הבאה המתבקשת.
- **שיעור נעילה 44%** — רוב הפספוסים הם הכדור שיוצא משדה הראייה.
- **תלות ביציבות פיזית** — כל הזזה של הצריח מחייבת כיול מחדש. גילינו את זה כשמצאנו הטיה של 3.7° בציר אחד בלבד, שהיא החתימה המובהקת של רכיב שזז.

הצגת מגבלה שמדדתם, עם המספר ועם ההסבר למה היא קיימת, חזקה יותר מהתחמקות ממנה.
