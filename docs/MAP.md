# מפת הפרויקט — מה כל תיקייה, ומה באמת בשימוש

התשובה הקצרה: **המערכת עצמה היא 7 קבצים.** כל השאר הוא ספריות, פלט אוטומטי, היסטוריה, או תיעוד.

---

## 1. הליבה — מה שבאמת רץ

| קובץ | תפקיד |
|---|---|
| `src/main.cpp` | הקוד **בתוך הארדואינו** — PWM למנועים, מיתוג לייזר, פרוטוקול UART |
| `vision/track_motion_3d.py` | **המעקב.** מאחד הכול: זיהוי → עומק → זוויות → פקודה |
| `vision/detector_dark.py` | **הגלאי** — מוצא את הכדור לפי ניגודיות מקומית |
| `vision/radar.py` | **קונסולת המכ"ם** — מיקום הכדור בס"מ, מבט מלמעלה ומהצד, וקו הלייזר |
| `vision/radar_sound.py` | צלילי המכ"ם, בת'רד נפרד |
| `vision/radar_replay.py` | מריץ את הקונסולה מהקלטה, בלי חומרה |
| `vision/stereo.py` | מפצל את הפריים לשתי עיניים |
| `vision/detector.py` | מגדיר את `Target` (המבנה שכל הגלאים מחזירים) |
| `vision/calib3d.json` + `aim_correction.json` | **נתוני הכיול** — בלעדיהם המערכת לא יודעת לאן לכוון |

**זהו.** ההדגמה רצה על שבעת אלה בלבד.

## 2. כלים שמריצים לפעמים — לא בזמן הדגמה

### כיול (רק אם החומרה זזה)

| קובץ | תפקיד |
|---|---|
| `vision/calib_ball.py` | אוסף נקודות כיול במרכוז אוטומטי על הכדור |
| `vision/fit_ball_calib.py` | מתאים מודל לנקודות, עם בחירה בבדיקה צולבת |
| `vision/ball_calib_points.json` | הנקודות שנאספו |

### מדידות (פעם אחת, התוצאה נשמרת)

| קובץ | מה מודד |
|---|---|
| `vision/measure_depth.py` | סקאלת העומק — הופך את המכ"ם לסנטימטרים |
| `vision/measure_latency.py` | ההשהיה מקצה לקצה — קובע את `LEAD_S` |
| `vision/agc_test.py` | האם המצלמה משנה בהירות בעצמה (AGC) — עצם כהה/לבן בחצי אחד, מדידת הקיר בחצי השני |
| `vision/depth_scale.json` | התוצאה של הראשון (נוצר בהרצה) |

### אבחון (רק כשמשהו לא עובד)

| קובץ | מתי |
|---|---|
| `vision/probe_cameras.py` | המצלמה לא נמצאת — מוצא את האינדקס שלה |
| `vision/stereo_view.py` | לבדוק שהמצלמה בכלל מוסרת תמונה |
| `vision/ball_tune.py` | הגלאי לא מזהה — מראה למה, עם מחוונים חיים |
| `vision/capture_ball.py` | שומר פריימים לדיסק לניתוח אופליין |
| `vision/aim_check.py` | מודד כמה הלייזר מפספס |

## 3. גלאים חלופיים — נשמרו בכוונה

לא בשימוש, אבל **כל אחד נכשל באופן מלמד** וזו הראיה שמצדיקה את הבחירה הסופית בדוח:

| קובץ | דגל | למה נפסל |
|---|---|---|
| `vision/detector_ref.py` | `--ref` | תמונת הייחוס מתיישנת כשה-AGC נודד |
| `vision/detector_shape.py` | `--shape` | ‏MOG2 מורח עצם נע לאליפסה |
| `vision/detector_motion.py` | `--motion` | תופס כל תנועה, כולל את המפעיל |
| `vision/autocal3d.py` | — | הכיול המקורי מול לוח. **יצר את `calib3d.json`** שעדיין בשימוש |
| `vision/fit_aim_correction.py` | — | גרסה מוקדמת, הוחלפה ב-`fit_ball_calib.py` |
| `vision/track_servo.py` | — | ניסיון לולאה סגורה חיה, לא יציב |

## 4. תיקיות שלא כתבנו — נוצרות לבד

**אף פעם לא עורכים אותן.** אם יימחקו, ייווצרו מחדש.

| תיקייה | גודל | מה זה |
|---|---|---|
| `.venv/` | 175MB | **הספריות של Python** — OpenCV, NumPy, PySerial. לא הקוד שלנו, אבל **חובה** להרצה |
| `.pio/` | 1.2MB | תוצרי הקומפילציה של הארדואינו |
| `vision/__pycache__/` | קטן | קבצי ביניים של Python |
| `.vscode/` | קטן | הגדרות העורך |

## 5. פלט וגיבויים — תוצרים, לא קוד

| תיקייה | מה יש בה |
|---|---|
| `vision/debug_images/ball/` | 15 הפריימים שעליהם השווינו את שלוש שיטות הזיהוי — **ראיה לדוח** |
| `vision/debug_images/aim/` | צילומי מדידות שגיאת הכיוון |
| `vision/debug_images/ballcal/` | צילומי נקודות הכיול |

`archive/` ו-`calib_backups/` הם היסטוריה בלבד. שווה לשמור לתיעוד ההתפתחות, אין להם שימוש חי.

## 7. לנקות את התצוגה ב-VS Code

הוגדר `.vscode/settings.json` שמסתיר את `.venv`, `.pio`, `__pycache__`, `archive` ו-`calib_backups` מסייר הקבצים.

**שום דבר לא נמחק** — רק הוסתר, כדי שהעץ שתציג יראה את המערכת ולא את הרעש. לבטל: לפתוח את הקובץ ולשנות `true` ל-`false`.
