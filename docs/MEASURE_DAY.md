# AeroEye-3D — יום מדידה ושיפור דיוק הפגיעה

מטרה: לגלות **למה** הלייזר מחטיא (גם כשהכדור עומד), לתקן לפי הממצא, ולהוכיח במספרים שהתיקון עזר.
כל הפקודות רצות מתיקיית `vision` (פותחים בה חלון PowerShell):

```
cd vision
```

> ⚠️ **בטיחות לייזר:** בכל השלבים הלייזר נדלק. לא להסתכל לקרן, ולוודא שאף אחד לא נמצא בקו הירי.
> ⚠️ רק תהליך Python אחד יכול להחזיק את המצלמה — לסגור את המעקב לפני כל סקריפט.

---

## שלב 0 — גיבוי המצב שעובד היום (דקה)

```
..\.venv\Scripts\python.exe calib_snapshot.py save demo_oct16
```

אם משהו משתבש בהמשך — חוזרים למצב הזה בפקודה אחת:

```
..\.venv\Scripts\python.exe calib_snapshot.py restore demo_oct16
```

## שלב 1 — בדיקת קשיחות (5 דקות)

לדחוף בעדינות את המצלמה ואת הצריח. אם משהו זז או מתנדנד — לקבע (ברגים / סרט / דבק חם) **לפני** המדידה.
כל תזוזה של הצריח או המצלמה מבטלת את הכיול, ולכן אחרי קיבוע חייבים לעבור לשלב 3.

## שלב 2 — מדידת "לפני" עם כדור עומד (15–20 דקות)

```
..\.venv\Scripts\python.exe aim_check.py COM4 1 --tag=before
```

- מחזיקים את הכדור דומם → `SPACE` → הצריח מכוון והתמונה קופאת.
- אם הצלב האדום לא על נקודת הלייזר — **לוחצים בעכבר על הנקודה האמיתית**.
- `ENTER` שומר, `X` מדלג, `R` מכוון מחדש.
- אחרי כל שמירה מודפס כיסוי של 27 התאים (רחוק / ביניים / קרוב × שמאל-מרכז-ימין × למעלה-אמצע-למטה). **מטרה: 20–30 דגימות, בכמה שיותר תאים**, כולל הצד הימני והחלק התחתון.
- `Q` מסיים ומדפיס דוח עם **פסק דין (verdict)**.

## שלב 3 — תיקון לפי פסק הדין

| פסק דין | משמעות | מה עושים |
|---|---|---|
| `CONSTANT` | כל המפה מוזזת באותה כמות — משהו זז | כיול כדור בלבד (3ב) |
| `POSITION` | ההחטאה תלויה במיקום בתמונה — המודל מנחש שם | סריקת לוח (3א) ואז כיול כדור (3ב) |
| `DEPTH` | קרוב ורחוק לא מסכימים — איבר הפרלקס | סריקת לוח ביותר מרחקים (3א) ואז 3ב |
| `SCATTERED` | אין דפוס פשוט | אם אחוז הפגיעה סביר — לא לגעת בכיול, לעבור לשלב 5 |

### 3א — סריקת לוח מחודשת (~5 דקות לכל מרחק)

הסריקה מכסה עכשיו את **כל** התמונה (Pan 25°–105°, Tilt 3°–55°; קודם הצד הימני לא נסרק בכלל).
הלוח צריך למלא את כל שדה הראייה של המצלמה, **כולל החלק התחתון**.

```
..\.venv\Scripts\python.exe autocal3d.py COM4 1 --reset
```

ואז להזיז את הלוח למרחק הבא ולהריץ **בלי** `--reset`, וכך הלאה — 6–8 מרחקים מקרוב לרחוק בטווח ההצגה:

```
..\.venv\Scripts\python.exe autocal3d.py COM4 1
```

`--reset` שומר גיבוי אוטומטי ומוריד את תיקון הכדור הישן (הוא לא תקף מעל מודל לוח חדש) — לכן חובה לבצע אחר כך את 3ב.

### 3ב — כיול מול הכדור (30–45 דקות)

```
..\.venv\Scripts\python.exe calib_ball.py COM4 1 --reset
..\.venv\Scripts\python.exe fit_ball_calib.py
```

(או `scripts\recalibrate.bat`, אבל הוא **לא** מאפס — אחרי קיבוע או סריקת לוח להשתמש בפקודה עם `--reset`.)
למלא את כל 27 התאים; הכדור לא נוגע בשפת התמונה (עיגול אדום = לא נרשם).

## שלב 4 — מדידת "אחרי" והשוואה (15 דקות)

```
..\.venv\Scripts\python.exe aim_check.py COM4 1 --tag=after
..\.venv\Scripts\python.exe aim_report.py aim_error_before.json aim_error_after.json
```

בסוף מודפסת השוואה: אחוז פגיעה, החטאה חציונית ושגיאה במעלות, לפני → אחרי.
**אם המצב החמיר:** `calib_snapshot.py restore demo_oct16`.

## שלב 5 — מדידת השהיה (5 דקות)

מכוונים את הלייזר לקיר במרחק 0.5–1 m, בלי מקור אור חזק בתמונה:

```
..\.venv\Scripts\python.exe measure_latency.py COM4 1
```

הסקריפט מדפיס `Suggested LEAD_S`. את הערך מעדכנים ב-`track_motion_3d.py` (שורת `LEAD_S = 0.05`).

## שלב 6 — בדיקה דינמית

מריצים את המעקב (`scripts\run_tracking.bat`), מניפים את הכדור ומצלמים וידאו בטלפון — זו ההוכחה לדוח ולהצגה.

---

**סדר זמנים משוער:** מסלול קצר (CONSTANT): כשעה. מסלול מלא (POSITION/DEPTH): שעתיים–שעתיים וחצי.
