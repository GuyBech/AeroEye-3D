# AeroEye-3D — מדריך תפעול

מדריך עצמאי: מה רץ איפה, איך מריצים, ומה עושים כשמשהו לא עובד.
גיא בכר · רז יחיאלי · מעבדה בחומרה, אוניברסיטת תל אביב.

---

## 1. ארכיטקטורה — מה רץ איפה

המערכת מפוצלת לשני מחשבים, וזה מכוון:

| רץ על | מה | למה שם |
|---|---|---|
| **המחשב (Python + OpenCV)** | עיבוד תמונה, סטריאו, חישוב זוויות | דורש כוח חישוב וספריות ראייה ממוחשבת |
| **Arduino UNO (C++)** | פיקוד PWM למנועים, מיתוג הלייזר | דורש תזמון קשיח ורציף שמערכת הפעלה לא מבטיחה |

**הקשר ביניהם:** ‏UART ב-115200 באוד. המחשב שולח שורת טקסט `PAN,TILT,LASER\n`, והלוח **מאשר מיד** (`OK 72 25 1`) ואז רודף אחרי היעד ברקע בצעדים של 1° כל 2 מילישניות.

הפיצול הזה קריטי: אם הלוח היה מסיים את התנועה לפני שהוא מאשר, המחשב היה נחסם ומאבד פריימים. במקום זה שני הצדדים רצים במקביל.

```
מצלמת סטריאו USB  ──►  PC / OpenCV  ──UART──►  Arduino UNO  ──PWM──►  צריח Pan-Tilt
   640×240                 זיהוי                  D9  = Pan                + לייזר
  שתי עיניים              + עומק                 D10 = Tilt
   320×240                + זוויות                D13 = לייזר
```

## 2. חומרה — לפני כל הרצה

☐ ‏Arduino UNO מחובר ב-**כבל ה-USB-B הכחול** של Elegoo (כבלים אחרים לא זוהו כלל)
☐ ספק חיצוני 5V מחובר למנועים וללייזר
☐ **GND משותף** בין הספק ללוח — בלי זה שום דבר לא יעבוד כמו שצריך
☐ מצלמת הסטריאו ביציאת USB משלה
☐ הצריח והמצלמה **לא זזו** מאז הכיול האחרון (ראו §6)

**מפת פינים (UNO):** ‏`D9` = Pan · `D10` = Tilt · `D13` = לייזר (הנורית המובנית על הלוח נדלקת יחד איתו — אינדיקציה נוחה).

## 3. הרצה יומיומית — שתי פקודות

### להריץ את המערכת

```bash
cd vision && ../.venv/Scripts/python.exe track_motion_3d.py COM4 1
```

זהו. בלי דגלים זה משתמש בגלאי הטוב ביותר. ייפתח חלון עם שתי העיניים; סגירתו או `q` עוצרים.

**מה רואים בחלון:**

| טקסט | מצב |
|---|---|
| `LOCK disp=32 -> pan=58 tilt=27` | נעילה מלאה — הלייזר דולק ועוקב |
| `COAST (holding)` | המטרה נעלמה לרגע; מחזיק כיוון 0.8 שנייה |
| `no motion (laser off)` | אין מטרה — הלייזר כבוי |

### לצרוב את הלוח (רק אחרי שינוי ב-firmware)

```bash
pio run -e uno -t upload --upload-port COM4
```

## 4. כל הסקריפטים — מה כל אחד עושה

### ליבה (התוצר)

| קובץ | תפקיד |
|---|---|
| `track_motion_3d.py` | **המעקב הראשי.** מאחד הכל: זיהוי → עומק → זוויות → UART |
| `detector_dark.py` | **הגלאי.** מוצא כדור כהה על רקע בהיר לפי ניגודיות מקומית |
| `radar.py` | **קונסולת המכ"ם** — מיקום הכדור בס"מ: מבט מלמעלה, מבט צד, נתונים וקו הלייזר |
| `radar_sound.py` | צלילי המכ"ם (פינג, נעילה, פתיחה), בת'רד נפרד כדי לא לעכב את המעקב |
| `radar_replay.py` | מריץ את הקונסולה מהקלטה, בלי חומרה — לחזרות |
| `stereo.py` | מפצל פריים 640×240 לשתי עיניים 320×240 באפור |
| `detector.py` | מגדיר את `Target` (המבנה המשותף) + גלאי בהירות לפנס |
| `src/main.cpp` | ה-firmware של הלוח |

בהרצה נפתחים **שני חלונות**: תצוגת המצלמה וקונסולת המכ"ם. ‏`--noradar` מבטל את השני, `--nosound` משתיק, `--fullscreen` פותח במסך מלא. בזמן הריצה: `F` מסך מלא, `M` השתקה. המכ"ם רק מקבל נתונים: הוא לא משפיע על הכיוון, ואם הוא נופל המעקב ממשיך בלעדיו.

### כיול

| קובץ | תפקיד |
|---|---|
| `calib_ball.py` | **איסוף נקודות כיול** — הצריח ממרכז את הלייזר על הכדור אוטומטית |
| `fit_ball_calib.py` | **התאמת המודל** לנקודות, עם בחירה בבדיקה צולבת |
| `aim_check.py` | מדידת שגיאת כיוון (כמה הלייזר מפספס) — לאימות |
| `autocal3d.py` | הכיול המקורי מול לוח שטוח — יצר את `calib3d.json` |

### מדידות (פעם אחת, ואז נשמרות)

| קובץ | מה מודד |
|---|---|
| `measure_depth.py` | **סקאלת העומק** — המודל הפשוט `Z = K/d`. לא מתאים למצלמה הזו, ראו למטה |
| `measure_latency.py` | **ההשהיה מקצה לקצה** — קובע את `LEAD_S` מנתונים במקום מניחוש |

**סקאלת עומק** — למה צריך: המערכת עובדת ב-`disparity`, שמספיק לכיוון אבל לא אומר "62 ס"מ". במצלמות מקבילות המרחק הפוך לדיספריטי: `Z = f·B/d`. אף אחד מהם לא כויל כאן, אבל **המכפלה שלהם היא קבוע יחיד**, וכך מדידה אחת קובעת אותו. הכלי מודד **פעמיים** במרחקים שונים — נקודה בודדת לא יכולה לגלות שהמודל שגוי. אם השתיים לא מסכימות, הוא **מסרב לכתוב** סקאלה ומשאיר את המכ"ם בדיספריטי גולמי, במקום להציג מספר שגוי בביטחון.

**עדכון 4.11 — היסט בין העיניים.** ב-5,395 פריימים הדיספריטי מול רדיוס הכדור הוא קו ישר, `d = 1.73 r − 15.8`, שלא עובר דרך האפס: הכדור גדל פי 3.2 והדיספריטי פי 10. לכן הנוסחה הנכונה כאן היא `Z = K/(d − d0)` עם `d0 ≈ −16`, ו-`radar.py` משתמש בה עם ערכים מוערכים מההקלטות. הסנטימטרים הם הערכה (בסטייה גסה של כ-15%). קובץ `depth_scale.json` עם `K` ו-`d0` יחליף את ההערכה, אבל `measure_depth.py` מודד רק `K` ולכן צפוי לסרב.

```bash
cd vision && ../.venv/Scripts/python.exe measure_depth.py 1
```

**השהיה** — הכלי שולח מדרגה של 20° לצריח ומודד פריים-אחר-פריים מתי המצלמה **באמת** רואה תזוזה. הפרשי הזמן מפרידים בין שני דברים שונים:

- **זמן מת** (פקודה → תחילת תנועה): ההשהיה הטהורה — UART, פירוק בקושחה, התנעת סרוו, חשיפה, העברת USB, חציצת דרייבר. **זה מה שהחיזוי צריך לבטל**, כי במהלכו הצריח עדיין מכוון לאן שהמטרה הייתה.
- **זמן התייצבות** (פקודה → עצירה): מוסיף את זמן המסע המכני, שתלוי בגודל הצעד ולכן פחות רלוונטי לתיקונים הקטנים והרציפים של עקיבה.

```bash
cd vision && ../.venv/Scripts/python.exe measure_latency.py COM4 1
```

הפניית הלייזר לקיר במרחק 0.5–1 מ' לפני ההרצה. בסוף הוא ידפיס ערך מומלץ ל-`LEAD_S`.

## 5. קבצי נתונים

| קובץ | מה יש בו |
|---|---|
| `calib3d.json` | **מפת הכיול הבסיסית** — מודל ריבועי מ-1290 נקודות סריקת לוח |
| `aim_correction.json` | **התיקון הפעיל** — שארית שנמדדה מול הכדור עצמו |
| `ball_calib_points.json` | נקודות הכיול הגולמיות של הכדור (הקלט ל-`fit_ball_calib.py`) |
| `aim_error.json` | מדידות שגיאת כיוון מ-`aim_check.py` |

**המודל:** ‏`pan = a₁x + a₂y + a₃·disp + a₄xy + a₅x² + a₆y² + a₇` (ו-tilt באותה צורה), כאשר `disp` היא ההיסטית הפיקסלים בין העיניים — היא שמקודדת את המרחק.

**התיקון מופעל מעל הכיול**, לא במקומו. `calib3d.json` נשאר כפי שהוא.

## 6. כיול מחדש — מתי ואיך

### מתי צריך

- **הצריח או המצלמה זזו** — הסימן: הלייזר מפספס בעקביות **לאותו כיוון**, גם כשהכדור עומד
- החלפתם מטרה לאחת בגודל שונה מהותית

### איך — שלושה צעדים

**צעד 1 — לאסוף נקודות**

```bash
cd vision && ../.venv/Scripts/python.exe calib_ball.py COM4 1
```

החזיקו את הכדור דומם → **רווח** → הצריח מתכנס לבד על הכדור ורושם. הזיזו את הכדור, חזרו.
**לחיצת עכבר** מסמנת את הנקודה ידנית אם הזיהוי טועה. **X** מבטל.

**צעד 2 — להתאים**

```bash
cd vision && ../.venv/Scripts/python.exe fit_ball_calib.py
```

**צעד 3 — לאמת:** להריץ את המעקב ולראות שהוא פוגע.

### כמה נקודות, ואיפה

| נקודות | מה נפתח |
|---|---|
| 8+ | תיקון קבוע (הזזה אחידה) |
| **20+** | תיקון ליניארי ב-x, y, ועומק |
| **55+** | כיול ריבועי מלא — מחליף את `calib3d.json` |

**פזרו על שלושת הצירים** — שמאל/מרכז/ימין, גבוה/נמוך, ובעיקר **קרוב/רחוק**. מודל שתלוי בעומק אבל נדגם רק בטווח צר יאקסטרפל גרוע מחוצה לו, ולכן הסקריפט מסרב למודל שאין לו מספיק נקודות לתמוך בו.

## 7. תקלות נפוצות

| תסמין | סיבה ופתרון |
|---|---|
| `could not open port 'COM4'` | תהליך Python אחר מחזיק אותו. לסגור אותו. |
| `camera opens but no frames` | אותו דבר — **רק תהליך אחד יכול לפתוח את המצלמה** |
| החלון לא נפתח | אם המצלמה לא מוסרת פריימים, הלולאה מסתובבת בלי להציג. לבדוק ששום דבר אחר לא מחזיק אותה |
| `COM4` לא קיים | הכבל. **רק כבל ה-USB-B הכחול** של Elegoo עובד |
| לא מזהה את הכדור | להריץ `ball_tune.py` ולראות למה נדחה. לרוב: תאורה חלשה → חשיפה ארוכה → טשטוש תנועה |
| הלייזר מפספס בעקביות לכיוון אחד | משהו זז. לכייל מחדש (§6) |
| הכל מפספס בתנועה מהירה בלבד | השהיה, לא כיול. להעלות את `LEAD_S` ב-`track_motion_3d.py` |

**לסגור תהליך Python תקוע (PowerShell):**

```bash
Get-Process python | Stop-Process -Force
```

## 8. הפרמטרים שכדאי להכיר

ב-`track_motion_3d.py`:

| פרמטר | ערך | משמעות |
|---|---|---|
| `DISP_MIN, DISP_MAX` | 3, 70 | טווח עומק קביל. תואם לכיסוי הכיול (2–57) |
| `COAST_S` | 0.8 | כמה זמן להחזיק כיוון אחרי אובדן מטרה |
| `ALPHA` | 0.7 | החלקה. גבוה = מגיב מהר, נמוך = יציב |
| `LEAD_S` | 0.05 | חיזוי קדימה. **קטן בכוונה** — הערכת מהירות רועשת, וחיזוי גדול מגביר רעש להתנדנדות |

ב-`detector_dark.py`:

| פרמטר | ערך | משמעות |
|---|---|---|
| `OPEN_D` | 29 | **הפרמטר הכי חשוב.** קוטר דיסק שמוחק את המוט ומשאיר את הכדור |
| `DELTA` | 22 | כמה רמות אפור הכדור צריך להיות כהה מסביבתו |
| `MIN_AREA / MAX_AREA` | 400 / 15000 | טווח גודל הכדור בפיקסלים |

`OPEN_D` הוא גם **מגבלת הטווח**: דיסק ברוחב 29 מוחק כדור קטן מ-~35 פיקסלים, כלומר כדור רחוק מדי. אם תרצו לעבוד רחוק יותר — להקטין אותו.
