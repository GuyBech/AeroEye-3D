# AeroEye-3D — סיכום פרויקט מקיף
*עודכן: 10/07/2026 · מעבדה בחומרה, TAU*

מערכת עקיבה אוטונומית: מצלמת סטריאו מזהה מטרה, המחשב ממיר את מיקומה לזוויות, וצריח Pan-Tilt מכוון אליה לייזר בזמן אמת.

---

## 1. ארכיטקטורת המערכת (Pipeline)

```
מצלמת סטריאו USB ──> Python/OpenCV ──> UART (COM3 @115200) ──> ESP32 ──> 2×Servo + לייזר
   (שתי עיניים)      זיהוי + כיול         "PAN,TILT,LASER\n"        PWM        (הצריח)
```

1. **מצלמה** (סטריאו מונוכרום, 640×240 → שתי עיניים 320×240) מצלמת את הסצנה.
2. **עיבוד תמונה** (Python) מזהה את המטרה בשתי העיניים → פיקסל (x,y) + עומק (disparity).
3. **מפת כיול** ממירה פיקסל+עומק → זוויות (pan, tilt).
4. **ESP32** מקבל פקודה ומזיז את המנועים; הלייזר נדלק רק כשיש מטרה.

## 2. חומרה

| רכיב | פרטים |
|---|---|
| בקר | ESP32 DevKit, מוזן מ-USB |
| מנועים | 2×MG90S — Pan=GPIO13, Tilt=GPIO14 (PWM 50Hz; Tilt במיפוי מורחב 400-2500µs) |
| לייזר | דרך טרנזיסטור 2N2222A + נגד 1kΩ, GPIO27 |
| כוח | מנועים+לייזר מספק 5V חיצוני; **GND משותף** עם ה-ESP32 (קריטי!) |
| מצלמה | סטריאו USB (אינדקס 1), פריים אחד = שתי עיניים זו-לצד-זו |
| מיקום | הצריח **צמוד למצלמה** (קורב כדי למזער פרלקס) |

## 3. Firmware — `src/main.cpp`

**פרוטוקול:** המחשב שולח `"PAN,TILT,LASER\n"` (למשל `90,25,1`); ה-ESP32 עונה `OK` **מיד** (לא חוסם).

**עקרון מרכזי — רדיפה לא-חוסמת (non-blocking chase):** הפקודה רק מעדכנת *יעד*; הלולאה הראשית מקרבת את המנוע ליעד ב-3° כל 5ms (עד ~600°/ש'). כך אין פיגור פקודות והמחשב יכול להזרים יעדים ב-30Hz+. (הגרסה המוקדמת רימפה *בתוך* הפקודה וחסמה — זה גרם ל-lag בעקיבה.)

**בטיחות:** clamping לטווחים (PAN 0-180, TILT 3-150; בפועל TILT≥15 מגבלה מכנית), לייזר נשלט ב-GPIO (כבוי כברירת מחדל).

## 4. עיבוד תמונה — מודולים (`vision/`)

העיקרון: **הגלאי הוא מודול מוחלף** — כולם מחזירים `Target(x, y, radius, area)` או `None`, כך שאפשר להחליף שיטת זיהוי בלי לגעת בשאר המערכת.

### `stereo.py` — פיצול סטריאו
`split_lr(frame)` חוצה את הפריים לשתי עיניים (שמאל/ימין). ה-**disparity** — הפרש המיקום האופקי של אותה מטרה בין העיניים (`x_left − x_right`) — הוא מדד העומק: גדל כשהמטרה מתקרבת (נמדד אצלנו 2 רחוק → 170 קרוב מאוד).

### `detector.py` — גלאי בהירות (פנס)
זיהוי **יחסי-לשיא** ולא בסף קבוע: מוצאים את הפיקסל הבהיר ביותר (`minMaxLoc`), ולוקחים את האזור בטווח `PEAK_DELTA` ממנו. יתרון: פנס נתפס **בכל מרחק** גם כשהוא נקודה זעירה — כל עוד הוא הדבר הכי בהיר. `ABS_FLOOR=90` מונע נעילה על קיר כשאין מקור אור.

### `detector_motion.py` — גלאי תנועה (עצם פסיבי)
Background subtraction ‏(MOG2): לומד את הרקע הסטטי, וכל דבר שזז מופיע כ-foreground. **בלתי-תלוי ברקע** — לא צריך רקע מיוחד. חסרון: עצם שנעצר "נעלם" (פתרנו חלקית עם COAST — ראו §6). Stateful — מופע נפרד לכל עין.

### `detector_shape.py` — גלאי צורה (כדור)
תנועה + סינון גאומטרי: לכל blob נע מחשבים **עגלגלות** (`4πA/P²`; עיגול=1) ו-**מילוי** (שטח מול העיגול החוסם). רק blob עגול מספיק (כדור טניס) עובר; יד נדחית.

## 5. כיול פיקסל→זווית — המסע והשיטה הסופית

### הבעיה
הפיקסל שבו מטרה נראית תלוי גם בזווית וגם **במרחק** (פרלקס — המצלמה והלייזר לא באותה נקודה). נדרש מיפוי `(x, y, עומק) → (pan, tilt)`.

### גלגולי הכיול (מה ניסינו ולמה)
1. **ידני דו-ממדי** (`calibrate.py`): המשתמש מכוון לייזר על מטרה בעכבר ולוחץ על הנקודה בתמונה. עבד, אבל מוגבל לשגיאת כיוון אנושית (~1-2°) ולמרחק אחד.
2. **ידני תלת-ממדי** (`calibrate_3d.py`): נוסף disparity כקלט שלישי. עדיין שגיאה אנושית, וגילינו שנקודות עם התאמת-סטריאו שגויה מזהמות את המפה → נוספה בדיקת שפיות (disparity חיובי הגיוני + אותה שורה בשתי העיניים).
3. **אוטומטי** (`autocal3d.py`, **השיטה הסופית**): בלי אדם בכלל —
   - הצריח סורק רשת זוויות צפופה (14×12).
   - בכל פוזה: צילום ממוצע עם לייזר **כבוי** ואז **דולק** → **חיסור פריימים** מבודד את נקודת הלייזר בשתי העיניים → פיקסל+disparity מדויקים, בלי שגיאה אנושית.
   - חוזרים על הסריקה ב-**14 מרחקי לוח** שונים (המשתמש מזיז לוח לבן; אין צורך למדוד מרחק — ה-disparity הוא מדד העומק).

### שתי תקלות זיהוי שנפתרו בדרך
- **זוהר הרכיב (glow):** בזוויות שבהן הנקודה מחוץ לפריים, ההפרש נתפס לזוהר קבוע של גוף הלייזר. פתרון: **מסנן חזרתיות** — פיקסל שחוזר בפוזות רבות הוא זוהר, לא נקודה (נקודה אמיתית זזה עם כל פוזה).
- **נקודה כפולה (ghost):** עדשת הלייזר הזולה מטילה נקודה ראשית + השתקפות חלשה ~20px לידה; ההפרש ננעל לפעמים על ה-ghost → הטיה קבועה של כמה מעלות בכל המערכת (!). פתרון: אחרי איתור אזור-השינוי, **הצמדה לפיקסל הבהיר ביותר בתמונת ה-ON** בסביבה — הנקודה האמיתית.

### המודל המתמטי
ריבועי (quadratic) עם עומק — 7 מקדמים לכל ציר:
```
pan  = a₁x + a₂y + a₃·disp + a₄xy + a₅x² + a₆y² + a₇
tilt = b₁x + b₂y + b₃·disp + b₄xy + b₅x² + b₆y² + b₇
```
- איבר ה-**disp** מתקן את הפרלקס השיורי (תלות במרחק).
- האיברים הריבועיים מתקנים **עיוות עדשה** (שגיאות שגדלות לקצוות — נצפה בפועל: המעבר מ-affine ל-quad חתך את שגיאת ה-Pan בחצי, 1.20°→0.57°).

### חישוב השגיאות והדיוק — איך זה עובד
1. בונים מטריצת מאפיינים A (שורה לכל נקודת כיול) ופותרים **ריבועים פחותים** (`np.linalg.lstsq`): המקדמים שממזערים את סכום ריבועי השגיאות.
2. **שארית (residual)** לכל נקודה: `|זווית_חזויה − זווית_אמת|` במעלות. מדווחים **ממוצע** ו-**מקסימום**.
3. **ניקוי חריגות איטרטיבי:** מתאימים → מסירים את הנקודה הגרועה ביותר → חוזרים, עד שהמקסימום ≤ סף (2.5-3°) או שנשאר מינימום נקודות. מסיר נקודות מדידה מושחתות בלי להטות את המפה.
4. **המרה אינטואיטיבית:** ‏1° ≈ 1.7 ס"מ במרחק 1 מ' (‏tan). כלומר שגיאת 0.8° ≈ ‏8 מ"מ ב-60 ס"מ.

### תוצאת הכיול הסופית
| מדד | ערך |
|---|---|
| נקודות שנאספו | 1804 (ב-14 מרחקים) |
| נקודות נקיות אחרי סינון | 1290 |
| כיסוי עומק | disparity 2–57 |
| **שגיאת Pan** | **ממוצע 0.82° · מקס 2.5°** |
| **שגיאת Tilt** | **ממוצע 0.47° · מקס 1.6°** |

זה קרוב לגבול הפיזי של סרוו הובי (backlash ~0.5-2°).

## 6. עקיבה בזמן אמת — `track_motion_3d.py`

הלולאה (לכל פריים):
1. זיהוי המטרה **בשתי העיניים** (גלאי לפי דגל: `--flash` בהירות / `--shape` כדור / ברירת-מחדל תנועה).
2. **בדיקת שפיות סטריאו:** ‏disparity בטווח הגיוני + הפרש שורות ≤ 40px. נכשל → אין נעילה → לייזר כבוי (הגנה מהתאמות-שווא).
3. המרה לזוויות דרך מפת הכיול.
4. **החלקה (EMA):** ‏`sm = α·raw + (1-α)·sm` עם α=0.7 — מדכא רעד בלי פיגור גדול.
5. **חיזוי מהירות:** אומדים מהירות זוויתית ומכוונים `LEAD_S` שניות קדימה — מפצה על ההשהיה מצלמה→עיבוד→סרוו בתנועה.
6. **COAST:** מטרה שנעלמה לרגע (עצם נע שנעצר) — מחזיקים את הכיוון האחרון 0.8ש' במקום לכבות מיד.
7. שליחת פקודות עד ~33Hz; **לייזר דולק רק כשיש נעילה** (או coast).

## 8. תקלות עיקריות ולקחים (כרונולוגי)

1. **נתיב עברית שבר את ה-toolchain של ESP32** → הקוד הועבר ל-`G:\My Drive\AeroEye-3D` (ASCII בלבד).
2. **GND מנותק במנוע Pan** → מנוע "מת"; אבחון בידוד: Tilt עבד ⇒ המסילה חיה ⇒ הבעיה בחוט הספציפי.
3. **מצלמה נפלה מה-USB שוב ושוב** → פתרון: כבל/שקע אחר + **להשאיר את המצלמה פתוחה ברציפות** (לא פתיחה-סגירה חוזרת). אומת ברצף 790 פריימים/40ש' ללא נפילה.
4. **קווי אות צפים:** חיבור ספק חיצוני בלי ESP32 גרם למנועים "להשתגע" — קו אות לא מחובר קולט רעש. פתרון: סדר הדלקה (קודם ESP32) + מומלץ pull-down ‏10kΩ.
5. **השתקפות זכוכית** בלבלה את הכיול האוטומטי הראשון (ננעל על תמונה ממוסגרת) → לוח מאט בלבד בשדה הראייה.
6. **glow + ghost** (ראו §5) — שתי תקלות הזיהוי המשמעותיות; ה-ghost היה גורם דיוק מרכזי.
7. **פרלקס:** ההפרדה הפיזית מצלמה-לייזר היא שורש הצורך בעומק; קירוב פיזי צמצם אך לא ביטל — נשאר איבר disp במודל.
8. **אל תסובב סרוו מוזן בכוח** — הוא מתנגד (מחזיק פקודה); סיבוב בכוח שובר גירים.

## 9. מצב נוכחי ומה הלאה

**עובד ואומת:** צריח + לייזר + פנס: זיהוי, כיול רב-עומק, עקיבה עם חיזוי — "יחסית מדויק... בסוף הוא יחסית קרוב" (בדיקת משתמש 10/07). דיוק סטטי טוב; פיגור קטן בתנועות מהירות.

**בעבודה / פתוח:**
1. **לולאה סגורה** (`track_servo.py`) — לתקן את זיהוי נקודת-הלייזר לצד פנס (הניסיון הראשון החמיר את המצב; הוחזר לגרסה הפתוחה). זה המפתח לדיוק "מושלם".
2. **מעבר למטרה האמיתית** — עצם תלוי על חוט: גלאי תנועה/צורה (מוכנים) + הגדרת "טווח פגיעה" מקובל במקום דיוק-נקודה.
3. **חומרה:** נגדי pull-down ‏10kΩ ל-3 קווי אות (fail-safe).
4. גבול הדיוק הנוכחי ~0.5-1° נובע מהסרוו (backlash) — שיפור נוסף דורש מנועים טובים יותר או לולאה סגורה.
